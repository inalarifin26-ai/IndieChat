# Indie — Independent Intelligence

Personal agentic messaging platform: **Messages · Agents · Workflows · Vault · More**,
built from `PERSONAL_AGENTIC_PLATFORM_SPEC.md` / `DEVELOPER_PROMPT.md` / the two
`CLAUDE_PROJECT_*.md` files in your package.

This build talks to a **real backend** (the sibling `indie_backend` package):
real auth with a Personal ID + 12-word recovery phrase, real Consent/Approval
and Execution Engines, a real Personal Vault with an explicit Share Result
endpoint, and a **live workflow execution feed over Server-Sent Events** — no
more in-memory mock data. See "What's real vs. simulated" below for exactly
what is and isn't wired up yet.

## Why you run this yourself

Flutter apps need the Flutter SDK, an Android/iOS toolchain, and either an
emulator or a physical device — none of which exist in the sandbox that built
this package. So the steps below are exactly what to run **on your own
machine**, where you already have (or will install) Flutter.

## 0. Start the backend first

This app has nothing to show without `indie_backend` running — see that
package's own README for setup (`npm install && npm start`, needs
Node ≥ 22.5). Leave it running in a separate terminal on `http://localhost:4000`.

## 1. Prerequisites

- Flutter SDK 3.19+ (`flutter --version`). Install: https://docs.flutter.dev/get-started/install
- Android Studio (for the Android SDK/emulator) and/or Xcode (for iOS, macOS only).
- A device or emulator running.

## 2. Create the platform scaffolding

This package ships `lib/`, `assets/`, and `pubspec.yaml` only — not the
generated `android/`, `ios/`, `web/`, etc. folders, since those must be
generated by your local Flutter toolchain (they're machine/SDK specific).

```bash
flutter create --org com.indie.app --project-name indie_app indie_scaffold
cd indie_scaffold
# Now copy this package's lib/, assets/, pubspec.yaml, analysis_options.yaml
# over the freshly generated ones (overwrite when prompted):
cp -r ../indie_app/lib .
cp -r ../indie_app/assets .
cp ../indie_app/pubspec.yaml .
cp ../indie_app/analysis_options.yaml .
```

(Adjust the `cp` source path to wherever you unzipped `indie_app/`.)

## 3. Install dependencies

```bash
flutter pub get
```

## 4. Apply the Indie app icon

```bash
dart run flutter_launcher_icons
```

## 5. Point the app at your backend, then run it

The backend's base URL is a compile-time constant with a default meant for
the **Android emulator** (`10.0.2.2` is how it reaches your host machine).
Override it for other targets:

```bash
# Android emulator (default — no flag needed if backend is on the same machine)
flutter run

# iOS simulator (simulator shares the host's localhost)
flutter run --dart-define=API_BASE_URL=http://localhost:4000

# Physical device (phone and computer on the same Wi-Fi)
flutter run --dart-define=API_BASE_URL=http://<your-computer-LAN-IP>:4000
```

First launch shows the Indie splash, then the **onboarding screen** since
there's no session yet — see below.

## What to try

1. **Onboarding → "Create ID" tab.** Set any local credential (6+ characters)
   and tap **Create my Personal ID**. A 12-word recovery phrase is shown
   exactly once — check the box once you've noted it, then continue. This
   calls the real `/auth/register` endpoint with `seedDemo: true`, so your
   new account is immediately populated with the same demo contacts/agents/
   workflow the earlier mock build had.
2. **Agents tab** → tap **Marketing Agent** (flagged "Approval required").
   Open the approval card, tap **Review**, and approve or deny — this is a
   real `POST /consent/approvals/:id/resolve` call.
3. **Workflows tab** → open **Daily Marketing Report** → **Run now**. This
   starts a real execution server-side and opens a live SSE stream — watch
   each node light up node-by-node, pausing at **Publish update** with a
   "waiting for your approval" banner. Approve it to watch the stream resume
   and complete. Tap the history icon for the real timeline from
   `/workflows/executions/:id/timeline`.
4. **Workflows → pencil icon** → the **Workflow Builder**: every drag,
   connect, add-node, rename, duplicate, delete and validate call now hits
   the backend's builder endpoints directly.
5. **Vault tab** → open any output → **Share result** → this calls
   `POST /vault/outputs/:id/share` with only the fields you checked; the
   response is the exact payload that "left" the Vault (nothing else exists
   server-side to leak).
6. **More → Consent Manager** → pause/revoke a mandate for real
   (`PATCH /consent/mandates/:id`). **More → Log out** ends your session
   (`/auth/logout`) and returns you to onboarding — try **Recover** there
   with the same recovery phrase to see the account come back with a new
   credential and every other session revoked.
7. **More → Connectors** → real list from `GET /connectors` (Google
   Calendar, Gmail, …). **Connect** opens the provider's own consent screen
   in your system browser (never inside Indie); approve there, then switch
   back to the app — it re-checks the connector list automatically when it
   regains focus. **Disconnect** revokes it. If the backend hasn't set up
   `GOOGLE_CLIENT_ID`/`SECRET` yet, the connector shows as "Unavailable"
   instead of erroring.

## Voice input in chats

Every chat surface (person/group chats, agent chats, the Orchestrator room) has a
**microphone** where Send would be while the box is empty. Tap to dictate, tap again to
stop; **long-press** for voice settings (language: Bahasa Indonesia / English, hands-free send).

- **Consent first.** The first tap shows what voice input does (the device's speech
  recognition makes the text — on some devices/languages that is an online service;
  Indie never receives or stores audio) and listens only after *Allow microphone*.
- **Nothing is sent for you** unless you turn on **Hands-free send** (off by default):
  then ending a command with “kirim” / “send” sends it. The keyword must be the last
  word, at least two words must remain, and “resend”/“kirimkan” don't count
  (`lib/core/voice_command.dart`, covered by `test/voice_command_test.dart`).
- Saying **“batal” / “cancel”** discards what you just dictated.
- Dictation is appended to text you already typed.

Setup after `flutter create .` (microphone + network permissions, idempotent):

```bash
python3 tool/add_platform_permissions.py                    # Android + iOS permissions
python3 tool/add_platform_permissions.py --allow-cleartext  # + http:// to your dev server (Android, DEV ONLY)
flutter pub get
flutter test                                                # includes the voice-command parser tests
```

Code: `lib/core/voice_service.dart` (wraps `speech_to_text`; only APIs shared by 6.x and
7.x are used), `lib/widgets/voice_input_button.dart` (mic + consent/settings sheet),
`lib/widgets/chat_composer.dart` (`ChatComposer(voice: true)`). The web preview has the
same feature on the Web Speech API (Chrome/Edge) with the same parser.

## What's real vs. simulated

| Area | This build |
|---|---|
| Auth: Personal ID, recovery phrase, session | **Real** — backed by `indie_backend`, JWT session persisted locally via `shared_preferences` |
| Navigation, screens, state transitions | Real Flutter/Dart, fully wired |
| Contacts vs. Agents separation | Real — enforced by data model & UI |
| Workflow graph + live execution | **Real** — server-driven state machine streamed over SSE, not a client-side timer |
| Workflow Builder (drag/connect/configure/validate) | **Real** — every op is a backend call; dragging itself stays local until drop, then persists |
| Consent/mandate/approval model | **Real** — enforced and stored server-side, scoped per account |
| Personal Vault / outputs / Share Result | **Real** — server-side storage; the shared payload is only ever what you opted into |
| External connectors (Google Calendar, Gmail) | **Real** — full OAuth round trip via the system browser; the app itself never sees or stores the tokens |
| AI Agents "thinking" | **Real when the backend has `ANTHROPIC_API_KEY` set** — falls back to scripted replies otherwise, same as the backend's own default |
| Node execution order | **Real** — the backend walks `workflow_connections` as an actual graph (parallel branches, fan-in, logic-node branch skipping) |

## Known rough edges (MVP-level, worth knowing before you dig in)

- The Workflows list shows "0 nodes" until you open a workflow once — the
  list endpoint intentionally omits the graph for speed; opening a workflow
  fetches and caches its full graph (`ensureWorkflowDetailLoaded`).
- If the backend restarts or is unreachable, most screens just show empty
  lists or a snackbar error rather than a dedicated offline state — there's
  no retry/backoff logic yet.
- `AppState` refetches whole lists after most mutations rather than patching
  precisely — simple and correct, but chattier than a production client
  would be.

## Project structure

```
lib/
  core/
    theme/              # brand colors + ThemeData (dark, calm, premium)
    api_client.dart      # HTTP + manual SSE client for indie_backend
  models/               # Contact, Agent, Workflow/Node/Execution, Consent/Approval/Output — with fromApi()
  state/
    app_state.dart        # AppState — auth, data loading, SSE-driven live execution, builder CRUD
  widgets/              # IndieMark/logo, avatars, node card, wire painter, consent + share sheets
  screens/
    splash_screen.dart    # bootstraps AppState, routes to onboarding or the shell
    onboarding_screen.dart # Create ID / Log in / Recover
    root_shell.dart        # 5-tab nav: Messages | Agents | Workflows | Vault | More
    messages/             # human Contacts chat
    agents/               # Agent Center, Agent Chat, Agent Dashboard
    workflows/             # Workflow list + live execution/builder canvas
    vault/                 # Personal Vault + output viewer
    more/                  # Consent Manager, Connector Manager, settings, logout
assets/images/          # Indie logo (icon, header lockup, full lockup, launcher icon)
```
