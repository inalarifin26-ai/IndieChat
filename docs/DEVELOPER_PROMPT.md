---

## NON-NEGOTIABLE PRODUCT RULES

### 1. Separate Contacts and Agents

Human contacts and AI agents must not appear in one mixed chat list.

Contacts:
- human conversations

Agents:
- autonomous digital workers

The user should immediately understand:

> Contact = communicates with me.
> Agent = works for me.

### 2. Workflow privacy

In Phase 1:

A workflow is a private personal asset.

NEVER implement:
- shared workflow editing
- workflow collaboration
- team workflow access
- agency workflow access
- workflow public links
- shared workflow permissions

The only shareable object is an OUTPUT generated by the workflow.

### 3. Sharing

Implement:

Workflow → Output → User review → Share Result

Do not expose:
- workflow definition
- private workflow configuration
- credentials
- private memory
- execution internals

when a user shares a result.

### 4. Consent

Every data access and external action must be represented by permission/consent/mandate.

Autonomous execution is allowed only inside an active mandate.

If an agent attempts an action outside its authority:

PAUSE → REQUEST APPROVAL → WAIT → RESUME OR CANCEL.

### 5. Personal Vault

Treat the Personal Vault as the user's private storage domain.

Do not design the platform as a centralized social-data repository.

### 6. External services

External integrations are optional connectors.

They are not the primary identity, messaging, or private-storage layer.

Use scoped authorization and revocation.

# LIVE WIRING ANIMATION

The workflow builder must also work as an execution visualization.

When running:

- active nodes visually activate
- control/data pulses move along connections
- completed nodes become successful
- failed nodes become error states
- inactive branches remain inactive
- approval nodes pause
- execution resumes after approval

Do not expose model chain-of-thought.

Only expose operational information:
- current action
- node state
- progress
- elapsed time
- output
- error
- approval state

# DEVELOPMENT METHOD

Before implementing a feature:

1. Define data model.
2. Define state transitions.
3. Define permission boundary.
4. Define API/interface contract.
5. Define UI states.
6. Implement.
7. Add validation.
8. Add tests.
9. Verify privacy boundary.

Do not start by creating isolated screens without connecting them to the underlying state model.

---

# SECURITY RULES

Never:
- store raw recovery phrases
- expose credentials to the UI unnecessarily
- include connector secrets in workflow exports
- implicitly share personal data
- grant broad connector permissions when scoped permissions are possible
- allow an agent to bypass permission checks
- allow an external action without required authority

Every external action should pass through a permission/consent gate.
